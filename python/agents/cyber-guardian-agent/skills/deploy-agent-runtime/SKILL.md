# Deploying Cyber Guardian Agent to Vertex AI Agent Runtime

> [!NOTE]
> This skill guide was generated by the **Antigravity/Jetski** coding agent in July 2026.
> Before executing this workflow for the first time locally, it is advised to check the GitHub repository for the latest version and updates.

This guide outlines the end-to-end workflow to fetch the cyber-guardian-agent source code, deploy it to the managed **Agent Runtime (Vertex AI Reasoning Engine)** on Google Cloud, and run validation tests.

---

## Prerequisites

Ensure you have the following CLI utilities installed:
- [gcloud CLI](https://cloud.google.com/sdk/docs/install)
- [uv](https://docs.astral.sh/uv/getting-started/installation/)
- `agents-cli` (Install using: `uv tool install google-agents-cli` then `agents-cli update`)

---

## Step 1: Sync Code and skills from GitHub

Clone the repository containing the agent samples and navigate to the agent directory:

```bash
# Clone the repository
git clone https://github.com/davxiao/adk-samples.git

# Navigate to the cyber-guardian agent directory
cd adk-samples/python/agents/cyber-guardian-agent
```

Initialize the Python virtual environment and download dependencies:

```bash
# Install the agents-cli tool globally (one-time setup)
uv tool install google-agents-cli

# Install dependencies and sync virtualenv
uv sync
```

## Step 2: Configure GCP Authentication & Project

Authenticate your shell to GCP and configure your target project:

```bash
# Authenticate gcloud CLI
gcloud auth login

# Set application default credentials for client libraries
gcloud auth application-default login

# Configure target project
gcloud config set project YOUR_PROJECT_ID
```

Ensure the necessary APIs are enabled in your target project:
```bash
gcloud services enable \
  aiplatform.googleapis.com \
  cloudbuild.googleapis.com \
  run.googleapis.com \
  bigquery.googleapis.com
```

---

## Step 3: Deploy to Agent Runtime

1. Verify `agents-cli-manifest.yaml` is configured with `deployment_target: agent_runtime`:
   ```yaml
   acli_version: 1.0.0
   name: cyber-guardian
   agent_directory: cyber_guardian
   create_params:
     deployment_target: agent_runtime
   ```

2. Run the deployment command:
   ```bash
   agents-cli deploy --project YOUR_PROJECT_ID --region us-central1
   ```

3. **Handling timeouts**: Agent Runtime deployments take 5 to 10 minutes because the platform builds a container image under the hood. If the CLI command times out or is interrupted, the deployment continues server-side. Check the status by running:
   ```bash
   agents-cli deploy --status
   ```
   Once successful, this updates the `deployment_metadata.json` with the deployed resource ID.

## Step 4: Verify Deployment with a Quick Test

Query your deployed agent using `agents-cli run`. The tool automatically handles authentication and session state:

```bash
# Run a quick test using the default example question
agents-cli run --mode adk "Run triage for hostname kvm01 and alert IOC_MATCH"
```

*Note: The CLI reads the engine resource ID from `deployment_metadata.json`. To target a specific URL or engine resource ID explicitly:*

```bash
agents-cli run \
  --url https://us-central1-aiplatform.googleapis.com/v1/projects/YOUR_PROJECT_ID/locations/us-central1/reasoningEngines/YOUR_ENGINE_ID \
  --mode adk \
  "Run triage for hostname kvm01 and alert IOC_MATCH"
```

## Step 5: (Optional) Publish Publicly Accessible A2A Agent Card

According to the [A2A Protocol Specification](https://a2a-protocol.org/latest/specification/), compliant agents must expose their details at `/.well-known/agent-card.json` to enable discovery. While the protocol standardizes the schema and URI path, it does not dictate network access policies. In default Agent Runtime deployments, the regional gateway enforces GCP IAM checks across all paths, blocking anonymous discovery.

To support public discovery of the basic Agent Card while keeping the backend execution endpoints (`rpc_url`) fully authenticated, you can host a static copy of the card publicly on a GCS bucket:

### 1. Generate the Agent Card JSON
Create a Python script (e.g., `generate_card.py`) in your project to compile the agent card using the ADK SDK:

```python
import asyncio
import json
from google.adk.a2a.utils.agent_card_builder import AgentCardBuilder
from a2a.types import AgentCapabilities, AgentExtension
from cyber_guardian.agent import root_agent

async def main():
    capabilities = AgentCapabilities(
        streaming=True,
        extensions=[
            AgentExtension(
                uri="https://google.github.io/adk-docs/a2a/a2a-extension/",
                description="Ability to use the new agent executor implementation",
            )
        ]
    )
    # Target URL pointing to your deployed Agent Runtime instance
    rpc_url = "https://us-central1-aiplatform.googleapis.com/reasoningEngines/v1/projects/YOUR_PROJECT_ID/locations/YOUR_REGION/reasoningEngines/YOUR_ENGINE_ID/api/a2a/cyber_guardian"
    
    agent_card = await AgentCardBuilder(
        agent=root_agent,
        capabilities=capabilities,
        rpc_url=rpc_url,
        agent_version="0.1.0",
    ).build()
    
    with open("agent-card.json", "w") as f:
        f.write(agent_card.model_dump_json(indent=2))

if __name__ == "__main__":
    asyncio.run(main())
```

Execute the script:
```bash
GOOGLE_CLOUD_PROJECT=YOUR_PROJECT_ID uv run python generate_card.py
```

### 2. Provision Public GCS Bucket & Upload the Card
Create a public read-only Cloud Storage bucket and upload the generated JSON card:

```bash
# 1. Create a Cloud Storage bucket (using dashes, not underscores)
gcloud storage buckets create gs://YOUR_BUCKET_NAME \
  --project=YOUR_PROJECT_ID \
  --location=YOUR_REGION \
  --no-public-access-prevention \
  --uniform-bucket-level-access

# 2. Grant public read permission (allUsers) to objects in the bucket
gcloud storage buckets add-iam-policy-binding gs://YOUR_BUCKET_NAME \
  --member=allUsers \
  --role=roles/storage.objectViewer \
  --project=YOUR_PROJECT_ID

# 3. Upload the card with the correct application/json content type
gcloud storage cp agent-card.json gs://YOUR_BUCKET_NAME/agent-card.json \
  --content-type=application/json \
  --project=YOUR_PROJECT_ID
```

You can now share the public bucket link (e.g. `https://storage.googleapis.com/YOUR_BUCKET_NAME/agent-card.json`) for agent discovery, while actual runtime queries remain authenticated.
